# Image Chat: text-to-image with FLUX

Users sign in, type a prompt in a chat-style page and get an image generated by
**FLUX.2 [klein] 4B**. Previous prompts and images stay in their history.

```
frontend/   Next.js chat page (deploys free on Vercel). Holds NO secret keys.
backend/    Python FastAPI: login check, daily limits, validation, talks to the image worker.
worker/     FLUX image worker (Phase 2: on your laptop, Phase 3: RunPod Serverless GPU).
supabase/   Database setup script (history, daily limits, private image storage).
```

How a request flows: **browser → backend (checks login and limits) → worker (makes the image) →
backend saves it in Supabase Storage → browser shows it.**

## Phase 1 setup (about 20 minutes, all free)

You need: Node.js, Python and `uv` (already on your laptop), and a free **Supabase** account.

### Step 1: Create the Supabase project (login + database + image storage)
1. Go to <https://supabase.com>, click **Start your project** and sign up (GitHub or email). The
   free plan needs no card.
2. **New project**: give it a name, set a database password (save it somewhere), pick the region
   closest to your users, then **Create**. Wait about 2 minutes.
3. Open **SQL Editor → New query**, paste the whole file [supabase/schema.sql](supabase/schema.sql)
   and click **Run**. It should say "Success. No rows returned".
4. Open **Project Settings → API Keys**. Copy:
   - the **Project URL** (`https://xxxx.supabase.co`),
   - the **Publishable key** (`sb_publishable_...`): goes in the frontend, safe for browsers,
   - the **Secret key** (`sb_secret_...`): goes in the backend only. **Never share or commit it.**

   If you only see `anon` / `service_role` keys, click **Create new API keys** first.
5. **Authentication → URL Configuration**: set **Site URL** to `http://localhost:3000`.
6. Email confirmation: Supabase's built-in email sender only delivers to your **own team's email
   addresses** and only a few emails per hour. For testing, sign up with the same email you used
   for Supabase. Before inviting 20-30 users, either set up custom SMTP (Phase 4) or rely on Google
   login.

### Step 2: Run the backend (PowerShell)
```powershell
cd E:\Ai_Image_Generation_Model\backend
copy .env.example .env
notepad .env        # fill SUPABASE_URL and SUPABASE_SECRET_KEY, save
$env:UV_CACHE_DIR = "E:\Ai_Image_Generation_Model\.cache\uv"   # keeps downloads off the full C: drive
uv sync
uv run uvicorn app.main:app --reload --port 8000
```
Check <http://localhost:8000/health>. It should show `{"ok":true}`. Leave this window open.

### Step 3: Run the frontend (a second PowerShell window)
```powershell
cd E:\Ai_Image_Generation_Model\frontend
copy .env.example .env.local
notepad .env.local  # fill NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY, save
$env:npm_config_cache = "E:\Ai_Image_Generation_Model\.cache\npm"
npm install
npm run dev
```
Open <http://localhost:3000> in Chrome.

### Step 4 (optional): Google login
1. <https://console.cloud.google.com> → create a project → **APIs & Services → OAuth consent
   screen** (External, fill app name and your email) → **Credentials → Create credentials →
   OAuth client ID** → type **Web application**.
2. Under **Authorized redirect URIs** add the callback URL shown in Supabase under
   **Authentication → Sign In / Providers → Google** (looks like
   `https://xxxx.supabase.co/auth/v1/callback`).
3. Paste the Google **Client ID** and **Client Secret** into that Supabase Google page, enable it,
   and save.

### Run the automated backend tests
```powershell
cd E:\Ai_Image_Generation_Model\backend
uv run pytest
```

## Configuration

Everything is set through environment variables. The full list, with comments, is in
[backend/.env.example](backend/.env.example) and [frontend/.env.example](frontend/.env.example).

| Setting | Default | Meaning |
|---|---|---|
| `WORKER_MODE` | `mock` | `mock` (placeholder), `local` (laptop GPU, Phase 2), `runpod` (Phase 3) |
| `MODEL_ID` | `black-forest-labs/FLUX.2-klein-4B` | Which FLUX model the worker runs |
| `DEFAULT_STEPS`, `DEFAULT_GUIDANCE` | per model | Override the recommended steps/guidance |
| `DAILY_LIMIT` | `10` | Images per user per day (resets 00:00 UTC) |
| `MAX_CONCURRENT_JOBS` | `2` | Images generated at the same time across all users |
| `RATE_LIMIT_PER_MINUTE` | `5` | Requests per user per minute |
| `MAX_PROMPT_CHARS` | `1000` | Longest allowed prompt |

Image sizes (about 1 megapixel each, sides divisible by 16): 1:1 = 1024×1024, 4:3 = 1152×864,
16:9 = 1360×768, 9:16 = 768×1360.

**Image formats:** every image is stored once as **lossless WebP** (no quality loss, about 1 MB).
Users pick **PNG, JPEG or WebP** when downloading (the Format dropdown in the prompt box, or the
Download ▾ menu on each image), and the backend converts at maximum quality (JPEG: quality 95, no
colour subsampling). SVG is not offered: FLUX makes pixel images, and a real SVG needs vector
tracing, which only suits logos and flat illustrations.

## App features
- ChatGPT-style layout: history sidebar grouped by date, search (Ctrl+K), ⋯ menu per image
  (download, copy prompt, reuse, delete), collapsible sidebar, new image (Ctrl+Shift+O).
- Under each image: Download ▾ (PNG/JPEG/WebP), copy prompt, regenerate, edit prompt, delete;
  click the image for full-screen view.
- Settings: theme (System/Light/Dark), default format, default aspect ratio, enhance by default,
  export prompt history, delete all images, account, keyboard shortcuts.

## Cost protection

Already active:
- **Daily limit per user** (`DAILY_LIMIT`), counted atomically in the database. A failed generation
  is not counted.
- **Max concurrent jobs** (`MAX_CONCURRENT_JOBS`) and **one job at a time per user**, so a few
  users can't run up the GPU bill.
- **Rate limit** per user per minute, and **prompt length limit**.
- **No keys in the browser.** Only the backend can call the GPU worker.

Added in Phase 3 (RunPod), before any money is spent:
- RunPod endpoint **max workers = 1–2** and **idle timeout ~5 s**, so GPUs stop billing right after a job.
- A **prepaid balance with auto-pay off**, plus RunPod low-balance email alerts.
- A worker **execution timeout**, so a stuck job cannot run for hours.

Free-tier limits to watch: Supabase free = 500 MB database, 1 GB file storage and 5 GB transfer
per month. At ~250 KB per image that is roughly 4,000 stored images.

## Security
- Secrets live only in `backend/.env` locally and in the hosting platform's secret settings in
  production. `.gitignore` blocks `.env` files, model weights and caches.
- The browser only gets the Supabase **publishable** key and the user's own login token.
- The database tables have Row Level Security on with no browser access. Only the backend's
  secret key can read and write them. The images bucket is private. Images are shown through
  links that expire after 1 hour.

## Troubleshooting
| Problem | Fix |
|---|---|
| Page says "Setup needed" | `frontend/.env.local` is missing or empty. Restart `npm run dev` after editing it. |
| "Cannot reach the server" | The backend is not running, or `NEXT_PUBLIC_API_URL` is wrong. |
| "Your session has expired" right after login | `SUPABASE_URL` in `backend/.env` doesn't match the frontend's URL. On an old project, set `SUPABASE_JWT_SECRET`. |
| "Image generation failed" | Look at the backend window for the `Supabase ... ->` error line. Usually `schema.sql` was not run or the secret key is wrong. |
| Images stop showing after an hour | The links expired. Refresh the page. |
| Sign-up email never arrives | See Step 1.6: use your Supabase account email, or Google login. |
